# Team OS — implementation plan

Spec: [`docs/specs/2026-08-30-team-os-design.md`](../specs/2026-08-30-team-os-design.md)
Language: [`CONTEXT.md`](../../CONTEXT.md)

**Goal:** Agents coordinate on a cheap board, go to court only for contradictions, get a compact inbox, and can be started from Crosstalk. Measure that with Quorum, three cells.

**Architecture:** Facade. Four MCP/CLI tools write today’s event kinds. One named contract amendment for `spoc`. Supervised runner waits in-process; attached agents still call `inbox`. Compose posts the job to `#floor`; the leader cuts tasks.

**Tech stack:** unchanged. Two runtime deps. `execFile` never `exec`.

TDD on every task. A test that passes on the first run has demonstrated nothing. Assertions must be able to fail. Cross-platform: a task is not done on one OS.

Do not implement this plan until the maintainer says to. The grill is closed; this is the record.

---

## Global constraints

- Node ≥ 20. `node:path`. `execFile` never `exec`. No `&&` in anything a human copies.
- Runtime deps remain `@modelcontextprotocol/sdk` and `yaml`.
- Log is append-only. Order by `seq`.
- No new event kinds.
- `falsifier` required on court raise / contest / amend. Not on `say` / `ack` / `done`.
- `uphold` still needs new evidence.
- Green on one platform is not done.
- No AI co-author trailers.

## Task 1 — Compact inbox projection

**Files:** new `src/core/inbox.ts`, `tests/core/inbox.test.ts`; daemon route `GET /inbox`; wire types next to the daemon contract (not a new event kind).

- [ ] Fold addressing events since `seq` into `InboxCard[]` with a one-line `summary` per kind.
- [ ] `mine` is metadata only (id, title, state) — same rule as today’s `board()`.
- [ ] `you` / `role` come from the presenting token.
- [ ] `next` is optional one line: assigned task, open claim against you, or idle.
- [ ] Waiter path matches `#awaitTurn` (same `addressesParticipant`), but the response is the compact object, not raw events.
- [ ] Attached cap remains 50s → `{ unread: [], next: "idle" }`.

**Tests:** a `message` to you becomes one `said` card; your own message does not; `task_created` assigned to you becomes `assigned`; raw `body` of a 2k message does not appear in `summary` (truncate); idle after 0ms timeout when `wait` is false.

**Break the code on purpose** once: make `summary` equal the full body and confirm the truncate test dies.

## Task 2 — Four-tool MCP surface

**Files:** `src/mcp/tools.ts`, `src/mcp/server.ts`, `tests/mcp/schemas.test.ts`, `tests/mcp/tools.test.ts`, CLI twins in `src/cli/index.ts`.

ListTools returns **only** `inbox`, `say`, `act`, `claim`.

| Tool | Maps to |
|---|---|
| `inbox` | `GET /inbox` |
| `say` | `POST /events` `message` (unchanged) |
| `act` `ack` | existing ack route; restatement required, ambiguities default `[]` |
| `act` `assign` | existing create-task + assigned (leader only) |
| `act` `done` | existing submit + `submitted`; critique may be `{ rounds: 1, critic: "self", findings: [] }` |
| `claim` `raise` / `respond` / `evidence` / `open` / `vote` | existing claim / decision routes |

- [ ] Each tool description is ≤ 200 characters. Delete the “> 60 chars or fail” rule; replace with “≤ 200 and names the verb.”
- [ ] Worker calling `act.assign` is `NOT_TASK_AUTHORITY`.
- [ ] `done` without a prior critique record still writes the short record (server fills the default).
- [ ] CLI: `crosstalk inbox|say|act|claim` with the same validation.

**Tests:** ListTools length is 4; names are exactly those four; a 201-character description fails the new schema test; `act.done` on a task with no critique produces a `self_review` event then `submitted`.

## Task 5 — Compose + spawn

**Files:** `src/cli/` compose command; hub compose overlay under `src/ui/`; `src/harness/runner.ts` connected to `harnesses.yaml` spawn argv.

- [ ] `crosstalk compose` (or `up --compose`) takes job text + participant list, writes config if needed, starts daemon, posts the job as `@human` on `#floor`, spawns supervisable participants.
- [ ] Hub: form for harness/seat/model, job textarea, Start. Same daemon routes. Verify in a browser: fill, start, `#floor` shows the job, roster shows spawned ids.
- [ ] PATH probe lists `claude` / `codex` / `cursor-agent` as available, others as attach-only.
- [ ] Attached participants print the new kickoff line and are not spawned.
- [ ] Confirm spawn argv against the installed CLI in the implementation session; update `harnesses.yaml` if `-p` / `exec --json` is wrong. Record the command you actually ran.

**Tests:** compose without a leader refuses; compose posts exactly one `#floor` message from `@human`; supervisable child is started via `execFile` (mock); GUI harness is not passed to `execFile`.

**Browser:** compose → Start → floor has the job → a spawned idle child does not appear as a second project folder. If the overlay can be opened while a daemon is already up, that path works too.

## Task 8 — Bench runner and rubric

**Files:** `bench/run.md` (operator script, not a `.sh`), optional `bench/score.ts` as a Vitest that reads three result folders.

- [ ] Three directories: `bench/results/solo/`, `github/`, `crosstalk/`.
- [ ] Each cell records: wall-clock, inbox/tool logs if any, final SHA, `typecheck`/`test`/`build` output, a look note (seed list visible y/n), whether the contradiction was named, operator minutes.
- [ ] `bench/score.ts` fails if vacuous-green is marked a win.
- [ ] Same `JOB.md`, same fixture SHA, two-hour box, same three models on both team cells, solo = strongest of those three — written as a checklist the operator cannot skip.

No automation that starts GitHub agents in this task. The runner scores artifacts after the operator has run the cells.
